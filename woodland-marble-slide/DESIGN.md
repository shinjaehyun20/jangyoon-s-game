# 숲속 구슬길 퍼즐 — 상세 게임 디자인 명세 v1

> 상태: `DESIGN_REWORK / LOCAL_CANDIDATE`  
> 대상: 장윤이(7세), 세로형 모바일 웹  
> 소스: 사용자 제공 YouTube Shorts `PAwWqFdftKU`의 **나무 레일 블록을 움직여 구슬을 목적지로 보내는 퍼즐 감각**  
> 구현 기준: `index.html`의 현재 4×4 슬라이딩 타일 후보를 그대로 예쁘게 꾸미는 것이 아니라, **놀이가 먼저 읽히는 목제 장난감 테이블**로 재구성한다.

## 0. 이번 재설계의 결론

현재 후보는 기술적으로는 "나무색 4×4 레일 타일"이지만, 시각적으로는 **HUD + 어두운 사각판 + 설명 모달**에 가깝다. 아이가 첫 3초 안에 "구슬을 어디서 어디까지 보내는지"를 못 읽는다.

새 방향은 **`세로로 놓인 실제 장난감 나무 보드`**다.

- 화면 위: 숲속 친구가 “어디까지 보내야 하는지” 보여준다.
- 화면 가운데: 만지고 싶은 두꺼운 나무 레일 조각, 빈자리, 빨간 구슬, 깃발.
- 화면 아래: 설명이 아니라 **즉시 행동하는 큰 두 버튼**.
- 완성 순간: 정적인 별 점수창 대신, 구슬이 실제 레일을 따라 움직이고 종점의 풍차/깃발이 반응한다.

**설계 문장:**  
`아이가 레일 조각을 밀어 길을 열면, 빨간 구슬 친구가 숲속 별빛 깃발까지 굴러가는 손맛 중심 퍼즐.`

## 2. 레퍼런스 DNA → 독창적 번역 경계

### 반드시 보존하는 감각

1. **손으로 만질 수 있는 목제 퍼즐 보드**: 화면 UI가 아니라 실제 장난감 같은 두께·홈·그림자.
2. **선명한 물리 목표**: 공/구슬이 출발점에서 목적지까지 이동한다.
3. **한 번에 읽히는 경로성**: 레일의 연결/단절이 아이 눈에 즉시 보인다.
4. **만졌을 때의 반응**: 움직일 수 있는 조각은 살짝 들리고, 막힌 조각은 부드럽게 흔들린다.

### 그대로 복제하지 않는 것

- 레퍼런스의 고유 캐릭터·UI·정확한 레이아웃·음원·이미지·카피는 사용하지 않는다.
- 레일은 기차 선로가 아니라 **숲속 작은 구슬 수로**로 바꾼다.
- 독창 놀이 동사는 “선로를 완성”에서 끝나지 않고 **구슬을 발사해 실제 길을 검증**하는 2단계다.

### 우리만의 시그니처

- **도토리 작업대**: 보드 네 귀퉁이에 작은 나뭇잎·도토리 장식. 게임 기능과 무관한 화면 장식은 최소화.
- **구슬 친구 ‘몽글’**: 단순 원이 아니라 하이라이트·그림자·눈 2개가 있는 빨간 구슬. 구를 때 몸이 회전한다.
- **목적지 ‘별빛 풍차’**: 구슬 도착 시 날개가 돌고, 별 조각이 풍차에 채워진다.

## 3. 첫 3초 읽기 경로

### 첫 화면은 모달이 아니라 보드 자체가 주인공이다

```text
[상단 14%]  숲속 구슬길 · 1-1 / 작고 단순한 진행 표시
[중앙 68%]  나무 보드 전체 + 빨간 구슬 출발 + 별빛 풍차 목적지
[하단 18%]  “레일 조각을 빈자리로 톡!” + [힌트] [새 퍼즐]
```

1. **0~1초**: 빨간 구슬과 금빛 풍차가 각각 0.7초 간격으로 한 번씩 통통 튄다.
2. **1~2초**: 빈칸 주변에서 실제로 이동 가능한 레일 조각 2~3개가 3px 위로 들렸다 내려온다.
3. **2~3초**: 손가락 아이콘이 한 번만 나타나 빈칸 옆 타일을 가리킨 뒤 사라진다.
4. 아이가 타일을 누르는 순간 튜토리얼은 종료한다. 별도 시작 모달·긴 설명을 두지 않는다.

### 초보자용 첫 판

- 첫 판은 완성까지 **2~3회 이동**만 필요하다.
- 움직일 수 없는 타일은 눌러도 경고색이 아니라 `툭` 하는 2px 좌우 흔들림 + “여기는 못 가요” 말풍선 0.8초.
- 첫 연결이 생기면 보드 상단의 작은 “길 찾는 중” 표식이 **“길이 이어졌어!”**로 바뀐다.
- 길이 전부 이어져도 자동으로 끝내지 않는다. 화면 하단에 큰 **`몽글 굴려 보내기`** 버튼이 등장한다. 아이가 원인(길 만들기)과 결과(굴러가기)를 연결하도록 한다.

## 4. 화면 설계 — 세로 390×844 기준

### 4.1 전체 레이아웃

| 영역 | 높이/위치 | 역할 | 설계 규칙 |
|---|---:|---|---|
| Safe header | 60px + safe-area | 돌아가기·레벨·별 | 제목은 한 줄, 숫자는 보조 |
| Mission strip | 42px | 현재 한 문장 목표 | 배경 카드 금지. 나뭇잎 모양 얇은 띠 |
| Toy board | 화면 가용 높이의 64~70% | 주 놀이 표면 | 최대 430px, 1:1 정사각형, 화면 중심 |
| Action dock | 74px | 힌트/새 퍼즐/구슬 발사 | 버튼은 최소 52px 높이 |
| Footer | 18px | 홈 링크·음소거 | 첫 화면에 시선 경쟁하지 않음 |

### 4.2 보드 단면

```text
  ┌─────────────────────────────────────┐
  │  풀잎/도토리 모서리 장식 (비기능)     │
  │  ┌───────────────────────────────┐  │
  │  │  □ □ □ □                       │  │
  │  │  □ □ □ □     4×4 레일 조각     │  │
  │  │  □ □ ▣ □     ▣ = 빈 홈        │  │
  │  │  ● □ □ ★     ●=몽글 / ★=풍차  │  │
  │  └───────────────────────────────┘  │
  │  나무 테두리 + 움푹 파인 안쪽 홈       │
  └─────────────────────────────────────┘
```

- 외곽 프레임: 14~16px, 둥근 카드가 아니라 **둥근 목재 판**. 모서리는 16px만 적용.
- 타일 간 간격: 5~6px. 너무 촘촘한 3px gap 금지.
- 각 타일: 1) 윗면, 2) 짙은 옆면(4px), 3) 보드에 닿는 그림자 3층으로 분리.
- 빈 홈: 검은 구멍처럼 만들지 않는다. **보드 안쪽의 비어 있는 따뜻한 목재 홈**이며, 옅은 점선/작은 화살표로 이동 가능성을 안내한다.
- 레일: 폭 46~52%의 도랑. 외곽은 진한 호두나무, 중앙은 크림색 구슬길, 가장자리는 얇은 하이라이트.

### 4.3 타일의 상태별 외형

| 상태 | 시각 처리 | 입력 피드백 |
|---|---|---|
| 기본 | 밝은 목제 윗면, 미세한 결 2~3개 | 없음 |
| 이동 가능 | 외곽 금빛 2px + 3px lift | 100ms 눌림 → 빈 홈으로 180ms slide |
| 이동 불가 | 채도 정상, 강조 없음 | 2px 흔들림만 |
| 힌트 대상 | 길게 반짝이지 않음. 1.2초 가는 빛 테두리 | 한 번만 펄스 |
| 연결 경로 | 레일 중앙에 아주 옅은 금빛 흐름 | 구슬 발사 버튼 활성화 |
| 구슬 진행 중 | 현재/다음 타일에 작은 빛 반사 | 입력 잠금 |
| 완성 | 타일 전부 흔들지 않음. 풍차·별·구슬만 반응 | 다음 스테이지 CTA |

- CSS gradient만으로 광택 플라스틱처럼 만들지 않는다.

## 6. 컴포넌트 명세

### 6.1 헤더

- 좌측: 원형 44×44 `←` 버튼. 홈으로 이동 전 현재 진행은 localStorage에 자동 저장.
- 중앙: `숲속 구슬길` / 하단에 작게 `숲길 1-1`.
- 우측: 별 항아리 버튼 44×44. 누르면 현재 수집 별과 잠긴 다음 숲길을 작은 시트로 보여준다.
- `스테이지 / 움직임 / 최고 별` 3개 큰 숫자를 고정 상단에 배치하지 않는다. 움직임은 보드 바로 위의 작은 칩 하나로만 보인다.

### 6.2 미션 스트립

상태 4종:

1. `레일 조각을 빈 홈으로 톡!`
2. `길이 이어졌어! 몽글을 보내 봐.`
3. `몽글이 가는 중…`
4. `도착! 별빛 풍차가 돌아가요.`

각 상태는 아이콘 1개 + 16자 내외. 개발자 상태 문구나 “connected=true” 같은 내부 용어 금지.

### 6.3 액션 도크

| 상태 | 좌측 버튼 | 우측 버튼 | 기본 강조 |
|---|---|---|---|
| 시작/퍼즐 중 | `💡 힌트` | `↻ 새 퍼즐` | 없음 |
| 길 연결 | `↻ 다시 고치기` | `몽글 굴려 보내기` | 우측 금빛 |
| 구슬 진행 | 비활성 | `몽글이 가는 중` | 진행 링 |
| 완료 | `같은 길 다시` | `다음 숲길` | 우측 금빛 |

- 버튼 모두 52px 이상, 실제 hit area 56px 이상.
- 힌트는 랜덤 인접 타일을 보여주면 안 된다. **사전 계산된 solution move의 다음 한 수**를 강조하고, 첫 2회까지만 무료. 이후에도 막지 말고 “한 번 더 볼래?”로 사용.

### 6.4 결과 시트

전체 화면을 어둡게 덮는 모달을 기본으로 쓰지 않는다. 보드는 유지하고, 하단에서 42% 높이의 밝은 나무/크림 시트가 올라온다.

- 풍차/구슬 애니메이션이 끝난 후 시트를 표시.
- `별 1~3개`, `이번엔 8번 만에 길을 찾았어!`만 표시.
- 비교·순위·실패 언어 금지.

## 7. 상호작용·상태 전이

```text
INTRO_GUIDE
  └─ 타일 탭 → PUZZLING
PUZZLING
  ├─ 인접 타일 탭 → MOVE_TILE → PUZZLING
  ├─ 비인접 타일 탭 → BLOCKED_NUDGE → PUZZLING
  ├─ 정답 한 수 힌트 → HINT_PREVIEW → PUZZLING
  └─ 레일 완전 연결 → PATH_READY
PATH_READY
  ├─ 타일 탭 → PUZZLING
  └─ [몽글 굴려 보내기] → MARBLE_RUN
MARBLE_RUN
  ├─ 레일 오류 감지 → GENTLE_STOP → PUZZLING
  └─ 목적지 도착 → CELEBRATE → RESULT_SHEET
RESULT_SHEET
  ├─ [같은 길 다시] → PUZZLING
  └─ [다음 숲길] → INTRO_GUIDE
```

### 이동 규칙

- 인접(상·하·좌·우) + 고정 타일 아님 + 빈 홈이면 이동 가능.
- 타일 이동은 180~220ms, ease-out. 동시에 두 타일이 사라졌다 나타나는 re-render 금지.
- DOM 재렌더 대신 타일 위치를 FLIP 방식 또는 CSS transform으로 보간한다. 7세 아이는 “미끄러져 갔다”를 봐야 한다.
- 연속 탭은 애니메이션 종료 전 입력 큐 1개만 허용. 다중 이동으로 보드가 깨지지 않게 한다.

### 구슬 주행 규칙

- `PATH_READY`가 된 후에만 주행 버튼을 노출한다.
- 경로는 `start → ... → end` 배열로 명시적으로 산출한다. 단순 true/false 연결 결과만으로는 애니메이션 불가.
- 각 타일 구간은 180~240ms. 모서리는 80ms 감속 후 방향 전환.
- 구슬은 레일 중심을 따라 `translate + rotate`하고, 타일 경계에서 작은 접지 그림자가 이동한다.
- 중간에 별 도토리가 있는 고급 스테이지는 구슬이 지나갈 때 별을 흡수한다.

### 무한 루프/저작권 안전

- 캐릭터·음악·영상·고유 에셋을 레퍼런스에서 추출하지 않는다.
- 모든 도형/재질은 CSS·SVG·Canvas로 새로 생성한다.
- 자동 반복 애니메이션은 작은 배경 잎 흔들림(4~6초)과 시작 안내 1회만. 집중을 방해하는 계속된 반짝임 금지.

## 8. 레벨 설계

### 월드 구조

| 월드 | 스테이지 | 새 요소 | 성공 감정 |
|---|---:|---|---|
| 1. 도토리 뜰 | 1-1~1-6 | 직선·L자 레일, 2~6번 이동 | “내가 길을 만들었어” |
| 2. 이끼 바위길 | 2-1~2-8 | T자 갈림길, 막힌 레일, 별 1개 | “어느 길이 맞지?” |
| 3. 반짝 시냇물 | 3-1~3-8 | 다리 타일, 두 구슬 중 하나 선택 | “순서를 생각했어” |
| 4. 부엉이 숲 | 4-1~4-10 | 회전 가능한 특수 타일 1개 | “움직이고 돌렸어” |
| 5. 별빛 풍차 언덕 | 5-1~5-10 | 구슬 2개 순차 발사·보너스 길 | “내가 설계한 길이야” |

### 1-1 상세

- 시작: 좌하단 몽글 집, 목표: 우상단 풍차.
- 빈 홈: 가운데 아래.
- 해법: 인접한 직선 레일 2개 + L자 레일 1개 이동.
- 첫 이동: 이동 가능한 타일이 스스로 한 번 들린다.
- 성공: 구슬 주행 1.6초, 풍차 회전 1.0초, 별 3개 중 1개가 채워짐.

### 별 판정

| 등급 | 기준 | 표현 |
|---|---|---|
| 3별 | 목표 이동 수 + 1 이내 | 별 3개, `길찾기 달인!` |
| 2별 | 목표 이동 수 + 5 이내 | 별 2개, `아주 잘 찾았어!` |
| 1별 | 그 외 완주 | 별 1개, `몽글을 도와줬어!` |

- 1별은 항상 획득 가능. “실패” 상태를 만들지 않는다.
- 목표 이동 수는 각 퍼즐의 실제 solution path 기준으로 고정한다.

## 9. 사운드·햅틱(옵션)

기본은 무음 재생 가능. 버튼은 모두 시각 피드백만으로 완결되어야 한다.

| 이벤트 | 소리 | 햅틱 |
|---|---|---|
| 타일 이동 | 낮은 나무 `tok` | light |
| 이동 불가 | 부드러운 `bum` | 없음 |
| 길 연결 | 짧은 글로켄 2음 | light |
| 구슬 회전 | 작고 낮은 롤링 | 없음 |
| 도착 | 풍차 종소리 3음 | medium |

- Web Audio만 사용하며 외부 음원 파일 없음.
- 첫 실행은 사운드 아이콘 `켜기`가 아닌 **음소거 상태**. 사용자가 원할 때만 활성화.
- `prefers-reduced-motion`이면 구슬 이동 시간을 0.55초 이하로 줄이고 파티클 제거.

## 10. 접근성·반응형 기준

- 가로 320px~480px: 보드는 화면 너비 기준. 390px에서 보드 최소 334px 확보.
- 세로가 짧은 568px: 헤더/미션을 1줄로 압축하되 타일은 64px 이상 유지.
- 모든 버튼/타일 hit target 최소 44×44px, 권장은 52px 이상.
- 각 타일의 접근성 이름: `2행 3열, ㄴ자 레일, 빈 홈으로 이동 가능`처럼 상태 포함.
- 색만으로 연결 상태를 알리지 않는다. 연결 경로는 금빛 흐름 + 작은 점선 움직임을 병행.
- 키보드: Tab으로 타일 이동, Enter/Space로 선택. Escape로 결과 시트 닫기.
- 색각 보정: 빨간 구슬만 목표 표지로 쓰지 않고 눈/하이라이트 + `몽글` 마크를 유지.

## 11. 구현 아키텍처 제안

### 파일 경계

```text
woodland-marble-slide/
├── index.html          # 실제 후보 게임, 단일 HTML 유지
├── thumb.svg           # 카탈로그용, 이번 명세 스타일과 동일한 목제 보드
├── DESIGN.md           # 이 문서
└── 99.old/             # 승인 후 폐기될 구 시안/검증 이미지 전용 (없으면 만들지 않음)
```

### JS 모듈 경계(단일 파일 안에서 함수 분리)

| 모듈 | 책임 |
|---|---|
| `puzzleModel` | 타일/빈 홈/고정물/이동 가능 여부 |
| `solutionEngine` | 각 레벨의 최단 수 및 `nextHintMove` 제공 |
| `pathResolver` | 시작→종점 경로 배열, 연결 상태, 구슬 좌표 |
| `boardRenderer` | 타일 DOM, SVG 레일, 목제 상태 클래스 |
| `motionController` | 타일 FLIP 이동, 구슬 주행, reduced-motion 처리 |
| `uiController` | 미션 문구, action dock, 결과 시트 |
| `progressStore` | 별/해금/음소거 localStorage 저장 |

### 금지 구현

- 타일 탭마다 전체 보드를 `innerHTML=''`로 재생성해 이동 모션을 없애는 방식.
- 연결됐다고 즉시 결과 모달을 띄우는 방식.
- 랜덤으로 힌트 타일을 고르는 방식.
- 텍스트 이모지를 구슬·목적지·레일의 최종 아트로 남기는 방식.
- 레퍼런스 영상/이미지를 캡처해서 게임 자산으로 넣는 방식.
